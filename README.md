# imgtools

Набор браузерных утилит для картинок, документов и видео: сжатие, правка EXIF, конвертация.
**Всё работает локально в браузере — файлы никуда не загружаются.** Это статический сайт без сборки и сервера.

## Возможности

### Компрессор (`batchcomp.html`)
- Сжатие JPG / PNG / WebP с ползунком качества и изменение размера в пикселях.
- Режимы подгонки: заполнить (с обрезкой), вписать (с полями), растянуть; сохранение пропорций; готовые пресеты размеров.
- **Обрезка мышью или пальцем.** Потяните по фото («До»), чтобы выделить нужную часть: за угол или любую сторону рамки (по всей длине, можно и чуть снаружи) её растягивают, внутри рамки перемещают; пропорции можно зафиксировать (1:1, 4:3, 16:9, как у оригинала и др.), Shift держит пропорции, Esc или клик вне рамки убирает её, стрелки сдвигают на 1 пиксель (Shift — на 10). Рамка работает в пикселях оригинала, поэтому результат точный до пикселя.
- **Растяжение рамкой.** У результата («После») есть белая рамка: тяните за углы и стороны, чтобы изменить итоговый размер — рамка может выходить за границы окна предпросмотра, а картинка растягивается прямо во время движения; Shift переключает «с пропорциями / свободно», свободное растяжение само включает режим «Растянуть». Размер вывода по умолчанию равен размеру рамки обрезки, а заданный вручную сохраняется.
- На телефоне рисование рамки по умолчанию выключено (чтобы страница листалась), включается кнопкой «✂ Обрезка».
- Один файл или пачка (ZIP), история обработанного.
- **HEIC** (фото с iPhone): расшифровывается и сжимается как обычное фото.
- **RAW** (ARW, CR3, NEF): используется встроенное в файл JPEG-превью камеры. Разрешение результата равно разрешению этого превью, а не матрицы.

### EXIF (`exif.html`)
- Просмотр метаданных JPG, удаление GPS или всех метаданных, смена даты съёмки.

### Converter (`imgconv.html`)
Тип каждого файла определяется автоматически, на странице появляются только подходящие ему форматы. Можно загрузить файлы разных типов сразу.

| Что на входе | Во что |
|---|---|
| Изображения (JPG, PNG, WebP, AVIF, BMP, GIF, **HEIC/HEIF**) | JPG, PNG, WebP, AVIF, GIF, BMP |
| Анимированный GIF | MP4, WebM |
| Документы: MD, TXT, HTML, DOCX | PDF, DOCX, HTML, TXT, MD (не в свой же формат) |
| Видео: MP4, WebM, MOV, MKV и др. (что читает браузер) | GIF; MP4, WebM, MKV, MOV |
| **MOD** (JVC), MPG, MPEG, VOB | GIF; MP4, WebM, MKV, MOV (через ffmpeg.wasm) |

Видео → видео: сохраняет звук, умеет менять качество, ширину, FPS, обрезать и убирать звук; если кодеки подходят новому контейнеру, видео и звук копируются без перекодирования. Видео → GIF: общая палитра на все кадры, опциональный дизеринг. MOD/MPG/VOB: деинтерлейс и выпрямление «широких» пикселей (16:9) делаются автоматически.

### Общее
- Кнопки «В компрессор →», «В EXIF →», «В конвертер →» передают результат на другую страницу (через IndexedDB).
- Тёмная и светлая темы, цвет акцента — настройки сохраняются в `localStorage`.
- PWA: устанавливается как приложение, после первого запуска работает офлайн (см. «Офлайн»).

## Запуск

Сборки нет — это обычные файлы. Открывать нужно **по HTTP(S), а не двойным кликом** (`file://`): сервис-воркер, воркеры, ES-модули и IndexedDB иначе не заработают, а WebCodecs (кодирование видео) требует https или `localhost`.

```bash
cd imgtools
python3 -m http.server 8000      # затем открыть http://localhost:8000
```

Разместить можно на любом статическом хостинге (GitHub Pages, Netlify, Cloudflare Pages, свой nginx).

## Публикация на GitHub Pages

1. Загрузите в репозиторий **содержимое** папки `imgtools` — файл `index.html` должен лежать в корне репозитория, а не во вложенной папке.
2. *Settings → Pages → Source: Deploy from a branch* → ветка `main`, папка `/ (root)`.
3. Через минуту сайт откроется по адресу `https://<пользователь>.github.io/<репозиторий>/`.

Все пути в проекте относительные, поэтому работа из подпапки не требует настроек. Самый большой файл — `ffmpeg-core.wasm.gz` (~10 МБ), остальные меньше 2 МБ, так что он проходит и через веб-загрузку GitHub (лимит 25 МБ на файл).

## Офлайн

Сервис-воркер (`sw.js`) кэширует страницы и локальные файлы при первом запуске. Тяжёлые декодеры (ffmpeg, libheif) скачиваются один раз при первом использовании и дальше берутся из кэша. Библиотеки с CDN и шрифты попадают в кэш после первого использования.

**При любом изменении файлов проекта поднимайте `CACHE` в `sw.js`** (например, `imgtools-v17` → `imgtools-v18`), иначе у посетителей может остаться старая версия.

## Ограничения

- **Браузеры.** Разрабатывалось и проверялось в Chromium (Chrome). Firefox, Safari и мобильные браузеры отдельно не тестировались: часть возможностей (WebCodecs, H.264, HEIC, перемотка видео) у них зависит от версии. Если что-то не работает, страница показывает причину.
- **Видео.** Браузер читает только те кодеки, которые умеет сам: например, MP4 с H.264 или HEVC может не открыться в Chromium без соответствующих кодеков. Файл обрабатывается целиком в памяти — многогигабайтные видео могут не поместиться.
- **MOD / MPG / VOB.** ffmpeg.wasm работает в один поток и заметно медленнее настольного ffmpeg: длинные записи конвертируются долго. Звук в WebM кодируется в Vorbis, потому что `libopus` в этой сборке падает на стерео.
- **GIF.** До 256 цветов; у анимированного GIF при конвертации в картинку берётся первый кадр; видео → GIF быстро растёт в размере (ширина × FPS × длительность).
- **HEIC.** Цветовой профиль (например, Display P3) не переносится — цвета могут быть чуть менее насыщенными. Обрезанные файлы отклоняются с сообщением. HEIC обычно легче JPEG, поэтому при сжатии экономия часто небольшая.
- **Не поддерживаются:** TOD, MTS/M2TS (JVC HD, AVCHD) и другие контейнеры, которые не читает ни браузер, ни Mediabunny, ни путь через ffmpeg для MOD/MPG/VOB.

## Для разработчиков

- Добавить формат документа: таблица `DOC_MAP` и функция `convertDoc` в `imgconv.html`.
- Форматы видео на выходе: `VID_TARGETS` (видео → видео), `ENC_CANDIDATES` (GIF → видео), `ffmpegArgs` (ffmpeg-путь).
- `ffmpeg-core.wasm.gz` — это `ffmpeg-core.wasm` из `@ffmpeg/core` 0.12.10, сжатый `gzip -9` без изменений содержимого; воркер распаковывает его сам при загрузке. Заменить: `gzip -9 -n -k ffmpeg-core.wasm` (флаг `-k` оставляет исходник).
- После правок поднимите версию кэша в `sw.js` (см. «Офлайн»).
